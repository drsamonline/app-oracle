Oracle

Two small things, both built only from what you actually give it: a compliment around one real detail you noticed, and a myth invented from what a photograph actually shows.

Open Oracle
Status Built and working offline: the compliment (detail required, carried verbatim, no flattery words), the kept list, the photo reading (palette, brightness, contrast, which third the light comes from), the myth, and the export.
Not built: a packaged Windows EXE / Android APK release (see the README). Face detection only where the browser provides FaceDetector — where it does not, the app says so rather than pretending it looked.
Compliment Give it one detail — “you rewrote the whole rota so Ravi could sit his exam” — and the compliment is built around that sentence, word for word. No detail, no compliment.
Portrait oracle A photo goes in; the app reads colour, light and composition — never the person — and invents a small myth from those numbers. It says it invented it, every time.

What it does

  • Refuses to produce a compliment with no detail behind it, rather than dressing up a generic one.
  • Carries the detail verbatim and says nothing else about the person.
  • Reads a photo's palette, brightness, contrast and which third the light comes from — and shows you those numbers.
  • Writes a myth that quotes at least two measured values, so it cannot be a template that fits any picture.
  • Labels the myth invented wherever it appears, including in the export.
  • Keeps what you choose to keep, on this device, and exports it as Markdown.

What it will not do

  • Flatter. No “amazing”, “wonderful”, “perfect” — the framing carries no praise adjectives at all, and a test checks the list.
  • Say anything about a person from a photo. No identity, no age, no gender, no ethnicity, no health, no mood. A last check blocks a myth containing any of those words before it is shown.
  • Keep a photo. It is drawn to a canvas, sampled, and the canvas is dropped. No data URL is ever written to storage.
  • Invent a myth from a photo it could not read. If a face detector is present and finds no face, it refuses and says so, with the photo still on screen.
  • Upload anything. No network at runtime; CSP connect-src 'none'.

When things go wrong

CaseWhat happens
Bad inputA missing detail asks for one instead of producing a generic compliment; a blank name is refused; a non-image file is refused by type.
No networkNothing changes — generation and the photo reading are on the device.
Storage full or unavailableThe compliment or myth is still generated and shown; keeping it fails with a notice saying it was not kept.
Corrupt saved stateAn unreadable kept list is reported and offered for export, and is never replaced by an empty list without you saying so.

How to run it

  • Here: play/index.html, or install it from your browser's menu.
  • Offline file: open docs/play/index.html straight from disk.
  • Tests: node tests/self-tests.js — the Compliment spec's countable “done means” is asserted there.
